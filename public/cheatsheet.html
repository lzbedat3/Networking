כמה לינקים / כמה חבילות
  • Store-and-forward: נתב מקבל את כל החבילה לפני שהוא משדר אותה הלאה.
  • חבילה אחת דרך N לינקים זהים: N·L/R (+props +procs).
  • P חבילות דרך N לינקים זהים: (N+P−1)·L/R.
  • קצבים שונים (R1,R2,R3): כל לינק L/Ri בנפרד וסוכמים. P חבילות: חבילה ראשונה עוברת את כולם, השאר מוגבלות ע"י צוואר הבקבוק: ΣL/Ri + (P−1)·L/Rmin.
  • Throughput (bits/sec) מקצה לקצה = min(R1..Rn) = צוואר הבקבוק. Bandwidth = כמות נתונים שהרשת מסוגלת להעביר ביחידת זמן.
  • "גודל החבילה כש-trans כולל T דרך K רשתות זהות R": L = T·R / K (למשל 4000ms, 4 רשתות, 3Mbps → 3,000,000 bit = 375,000 B).
מיתוג מעגלים מול מיתוג מנות
  • Circuit: משאבים שמורים (FDM תדר / TDM חריצי זמן), קצב מובטח, בזבוז כשאין שידור. חיסרון: פחות משתמשים יכולים לשתף את הרשת.
  • Packet: statistical multiplexing, store-and-forward, תורים ואובדן, אין קצב מובטח, יותר משתמשים.
  • TDM: קצב לכל משתמש = R / slots. זמן = setup + bits / (R/slots).
  • תרשים frequency×time עם פסים לאורך הזמן = TDM; פסים לאורך התדר = FDM.

UDP + Checksum
  • Best effort, connectionless, בלי flow/congestion control, בלי סדר. כותרת 8 בתים: src port, dst port, length, checksum. גודל מינימלי 8.
  • למה UDP: אין handshake, אין מצב, כותרת קטנה, בלי ויסות קצב (DNS, VoIP, streaming, QUIC). UDP + seq + ACK + retransmission = העברה אמינה.
Checksum: חיבור מילים של 16 ביט carry מחוץ ל-16 ביט → wraparound (+1) בסוף: היפוך כל הביטים (1's complement) מקבל: סוכם הכל + checksum = 1111…1 → תקין

TCP: Seq / ACK
  • point-to-point, full duplex, byte stream, MSS (לרוב 1460). כותרת מינ' 20 בתים.
  • Seq = מספר הבית הראשון בסגמנט. ACK = הבית הבא שמצופה (מצטבר).
Next Seq = Seq + Len (לא Seq+1!) SYN ו-FIN "צורכים" מספר אחד Telnet: A: Seq=42,ACK=79,'C' → B: Seq=79,ACK=43 אבד 1007, הגיע 1008 → ACK = Seq של 1007 (dup)
  • B בלי נתונים עדיין שולח ACKs (סגמנטים ריקים). ACK על piggyback כשיש נתונים.
  • TCP שולח מחדש גם ב-timeout (לא רק אחרי 3 dup ACKs).

שכבת האפליקציה: ארכיטקטורות ודרישות
  • Client-server: שרת תמיד דלוק, IP קבוע, data centers; לקוחות לא מדברים ביניהם. P2P: אין שרת קבוע, self-scalability, peers מתחלפים. Overlay network ב-P2P = peers + קשרי TCP לוגיים, בלי ראוטרים.
  • דרישות: data integrity (אמינות), throughput, timing, security. TCP: אמינות, flow, congestion, connection-oriented; לא: timing, throughput מובטח, אבטחה. UDP: כלום מזה.
  • socket = הממשק בין תהליך לשכבת התעבורה ("דלת"). מזהה תהליך = IP + port. Socket מזהה תקשורת בין שני תהליכים.
  • Cloud: מבוסס על מודל כלכלי (pay per use).
